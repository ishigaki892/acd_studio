# AtCoder Studio の使い方

インストール方法と最初の流れは [README](../README.md) にあります。このページでは、機能ごとの使い方を詳しく説明します。

## 画面の構成

- **左端（アクティビティバー）**：サイドバーに表示する内容を、「エクスプローラー」（⇧⌘E）・「検索」（⇧⌘F）・「実行とデバッグ」（⇧⌘D）・「コンテスト」（旗のアイコン。[コンテストの提出状況](#コンテストの提出状況)）から切り替えます。表示中のアイコンをもう一度押すとサイドバーが閉じます。いちばん下の歯車は設定です。
- **左（サイドバー）**：ファイル一覧など。⌘B で表示・非表示を切り替えます。
- **上（ツールバー）**：問題の選択欄と、「実行」「サンプルテスト」「ランダムテスト」「対話テスト」「デバッグ」「提出」のボタン。
- **中央**：エディタ（タブで切り替え）。
- **右**：問題文。右下は「提出結果」。
- **下**：「実行ログ」「テスト結果」「エラー一覧」「デバッグコンソール」「履歴」のタブ。

各ペインの境目はドラッグで調整できます。ウィンドウは 800 × 500 より小さくはなりません。

## 作業領域と信頼

問題を置くフォルダを「作業領域」と呼びます。「フォルダを開く」（⌘O）で選ぶと、次回の起動時にも同じフォルダとタブが開きます。

初めて開くフォルダでは「このフォルダを信頼しますか」と聞かれます。ビルドや言語サーバー（rust-analyzer・clangd・basedpyright）は、フォルダ内の設定（`build.rs` や `.cargo/config.toml` など）を通じてコードを実行することがあるためです。

- **「信頼する」**：すべての操作ができます。次からは聞かれません。
- **「信頼しない」**：ファイルの編集、問題の表示、問題フォルダの作成はできますが、実行・テスト・デバッグ・言語サーバー・提出はできません。次からは聞かれませんが、ファイル一覧の上の「信頼する…」から信頼し直せます（もう一度確認画面が出ます）。

## ファイル一覧

- 見出しの「＋」で新しいファイルを、その隣のボタンで新しいフォルダを、選択中のフォルダに作ります。
- 右クリックメニューから、ファイルは「名前の変更」「削除」、フォルダは「新しいファイル」「新しいフォルダ」「名前の変更」「削除」ができます（Esc で閉じます）。名前の変更では、大文字・小文字だけの変更もできます。
  - 削除したものはゴミ箱に移ります。フォルダを削除するときは、中のファイル数が確認画面に表示されます。シンボリックリンクはリンク自体を削除します（リンク先は残ります）。
  - フォルダの名前を変えると、その中のファイルのタブやブレークポイントも追従します。
  - 実行・テスト・デバッグ・問題の作成をしている間は、フォルダの名前の変更や削除はできません。
- Finder などで作業領域の中身を変えた場合は、IDE のウィンドウに戻ったときに一覧が更新されます。
- 左側の縦線でフォルダの階層が分かります。マウスを乗せると、その項目が属するフォルダの線が濃くなります。

## 検索

- アクティビティバーの虫眼鏡（⇧⌘F）で、サイドバーが「検索」に切り替わります。エディタで 1 行の範囲を選んでいれば、その文字列を検索します。
- 入力が止まって少しすると検索が始まります（Enter ですぐに検索）。右側のボタンで、大文字と小文字の区別（Aa）・単語単位（ab）・正規表現（.*）を切り替えます。正規表現の書き方は Rust の `regex` クレートに従います。
- 結果はファイルごとにまとめて表示されます。行を押すと、エディタでその場所に移動します。
- 検索の前に、未保存のタブは保存されます（検索は保存済みの内容を対象にするため）。
- 検索は 1 行単位です（複数行にまたがる一致は探しません）。`.git`・`target`・`node_modules` フォルダ、シンボリックリンク、1 MB を超えるファイル、テキストでないファイルは対象外です。表示する一致は 2,000 件までです。
- **置換**：検索欄の左の「▸」で置換欄を開き、「すべて置換」か、ファイルの行ごとの「置換」で置き換えます。置き換える前に確認ダイアログが出ます。正規表現では `$1` や `${名前}` でキャプチャを参照できます。`$1_x` のように数字のあとに文字が続いても、`$1` は 1 番目のキャプチャです。`$` そのものは `$$` と書きます。
  - 検索したあとで内容が変わったファイル（置換の直前に未保存の編集を保存したものも含む）は置き換えません。もう一度検索してから置換してください。
  - 置換の直後なら「置換を元に戻す」で戻せます。戻せるのは直前の 1 回だけで、次の置換・フォルダの開き直し・アプリの終了までです。置換のあとで編集したファイルは戻しません。

## 問題とコンテスト

### コンテストを作る

1. ファイル一覧の見出しの「⤓」を押し、コンテスト ID（例：`abc480`）を入れて「作る」（または Enter）を押します。言語（Rust・C++・Python）は、設定画面の「問題文」の「問題を作るときの言語」で決まります。
2. 問題の一覧を読み込み、1 問ずつ問題を取得して、作業領域の直下に次のようなフォルダを作ります。進み具合（例：「3 / 7：abc480_c」）と、問題ごとの結果が表示されます。

   ```
   abc480/
     .cargo/config.toml    ← ビルド結果の置き場所（target）をコンテスト内で共有する設定
     abc480_a/
       Cargo.toml          ← パッケージ名は問題 ID（数字で始まる場合は p_ を付ける）、edition 2024、雛形の依存
       src/main.rs         ← 雛形
       test/sample-1.in    ← サンプル
       test/sample-1.out
       …
       test/input.txt      ← 「実行」で使う標準入力（入力例 1）
       test/compare.json   ← 比較方法と制限（時間制限は問題の制限＋500 ms、メモリは問題の制限。誤差の指定があれば float）
     abc480_b/
     …
   ```

   C++ の場合は、`.cargo/config.toml` の代わりに `.clang-format` を置き、問題ごとに次のファイルを作ります。

   ```
   abc480/
     .clang-format         ← 整形スタイル（LLVM スタイル、インデント 4）。自由に書き換えて構いません
     abc480_a/
       main.cpp            ← 雛形
       compile_flags.txt   ← ほかのエディタの clangd 用のオプション（IDE の clangd は、IDE が渡すオプションを使います）
       test/…              ← Rust と同じ
   ```

   Python の場合、コンテストのフォルダには何も置かず、問題ごとに `main.py`（雛形）と `test/…`（Rust と同じ）だけを作ります。

3. 終わると、最初に作れた問題のファイル（Rust は `src/main.rs`、C++ は `main.cpp`、Python は `main.py`）が開きます。

- 作成中は「止める」で中断できます（取得中の問題を終えたところで止まります）。作り終えた問題はそのまま残ります。
- すでにあるファイルは上書きせず、結果に「すでにありました」と表示します。別の言語の問題フォルダ（例：Rust の `abc480_a/` があるところに C++ で作る）には、ファイルを追加せずにお知らせします。サンプルを削除した場合は、もう一度作ると削除したものだけを書き直します。中身を変えたサンプルは書き換えません（「中身が違うので書いていません」と表示）。
- AtCoder にアクセスするのは「作る」を押したときだけで、1 問ごとに 1 秒の間隔をあけます。一度取得した問題はアプリのフォルダに保存し、次からは再取得しません。
- 開始前のコンテストは問題の一覧が読めないので作れません。開催中のコンテストは、ログインしていれば作れます（ログインは [提出](#提出) を参照）。

### 1 問だけ作る

- 上の選択欄にコンテスト ID を入れて「一覧」を押し、問題を選ぶと、右に問題文が表示されます。
- 問題文の欄の「…」→「この問題を作る」で、その問題のフォルダだけを作ります。言語は、設定画面の「問題文」の「問題を作るときの言語」で決まります。開いているファイルのフォルダ名からすでに問題が決まっている場合（例：`abc480_a/` 内のファイル）は、このボタンは表示されません。

### 雛形

アプリのフォルダ（[データの場所](#データの場所)）の `templates/` に次のファイルを置くと、問題を作るときにその内容が使われます。置いていないものは、IDE 内蔵の最小限の雛形になります。フォルダは、設定画面（⌘,）の「テンプレート」にある「テンプレートのフォルダを開く」から開けます。

| ファイル | 使われる場所 | 置いていないとき |
|---|---|---|
| `templates/main.rs` | `src/main.rs` の内容 | `fn main() {}` |
| `templates/dependencies.toml` | `Cargo.toml` の `[dependencies]` の内容 | `proconio = { version = "=0.5.0", features = ["derive"] }` |
| `templates/main.cpp` | C++ の `main.cpp` の内容 | `#include <bits/stdc++.h>`、`using namespace std;`、入出力を高速化する 2 行だけの `main()` |
| `templates/main.py` | Python の `main.py` の内容 | 空の `def main():` と、それを呼ぶ `main()` |

`dependencies.toml` の例（バージョンはジャッジに合わせます）：

```toml
proconio = { version = "=0.5.0", features = ["derive"] }
ac-library-rs = "=0.2.0"
superslice = "=1.0.0"
itertools = "=0.14.0"
```

- `proconio` の `#[fastout]` を使うには `features = ["derive"]` が必要です（ジャッジも derive を有効にしています）。
- 雛形を変えても、すでに作った問題の `Cargo.toml`・`src/main.rs`・`main.cpp`・`main.py` は変わりません。

### 問題文の表示

- 問題文（日本語）・制限・数式が表示されます。見出しの右には「input! を作る」「サンプルを保存」と「…」が並びます。「…」からは、「再取得」（読み込み直し）・「公式ページ」（ブラウザで開く）・「この問題を作る」を選べます。見出しに並べるボタンは、設定画面の「問題文」で選べます。
- 画像は表示しません。画像があった場所には「［画像があります。公式ページで見てください］」と表示されます。
- 読み込めないとき（ネットワークにつながっていない、ページの構造が変わったなど）は、理由と「公式ページを開く」「もう一度試す」が表示されます。

### input! を作る

問題文の欄の「input! を作る」を押すと、問題文の「入力」の形式と「制約」から、proconio の `input!` の中身を作ります（保存済みの問題文を使うので、再取得はしません）。

- 整数の型は、制約で負の値がありうるなら `i64`、0 以上なら `usize` にします。制約から判断できないときは `i64` にして注意を出します。文字列は `Chars`、1 文字は `char`、実数は `f64` です。
- 変数名は、問題文の変数名を小文字にしたものです（縦に並ぶ組は名前をつなげます。`X_i Y_i` なら `xy`）。Rust の予約語と重なる場合は末尾に `_` を付けて（`fn_`・`if_` など）注意を出します。
- 作った形で入力例を読み込めるかを確かめます。合わないときは「入力例 N と合いません（…）」と表示されます。
- テストケースが複数ある問題では、`main()` 用（`t: usize`）と `solve()` 用（1 ケース分）に分けて作ります。
- クエリ（`query_1 … query_Q`）や読み取れない形式があると、その手前までを作り、残りはコメントと注意でお知らせします。

ボタンの使い方：

- **「solve() の input! を置き換える」**：エディタで開いている `.rs` ファイルの `fn solve` の中にある最初の `input! { … }` の中身を置き換えます（なければ `fn solve` の先頭に入れます）。⌘Z で元に戻せます。
  - テストケースが複数ある場合は、`main()` の `input!` も `t: usize` にします。`main()` に `input!` がなければ何もしないので、`for _ in 0..t { solve(); }` は自分で書いてください。
  - 設定画面の「問題文」で「テストケースが複数のとき、main() に for も書く」をオンにすると、`main()` に `input!` がなくても先頭に入れ、`main()` 内の `solve();` を `for _ in 0..t { solve(); }` に書き換えます（すでに `for` などの中で呼んでいれば、そのままにします）。
- **「コピー」**：作ったコードをクリップボードにコピーします。`fn solve` がないファイルではこちらを使ってください。

設定画面の「問題文」で「問題を作るときに input! を入れておく」をオンにすると、「コンテストを作る」「この問題を作る」のときに、テンプレートの `fn solve` の `input!` を自動で作ったものにしておきます（テストケースが複数ある場合は「main() に for も書く」の設定に従います）。作成結果には、問題ごとに「input! を入れました」（一部だけ作れたときや入力例と合わないときは、その旨も）か「input! を作れませんでした（理由）」が表示されます。作れなかった問題や、すでにある `main.rs` はそのままです。

作られた型や形は、必ず問題文と見比べてください。入力例と合っていても、型が正しいとは限りません。

#### C++ の場合

選んでいる問題の `<コンテスト>/<問題>/` が C++ のフォルダなら（フォルダがなければ、設定の「問題を作るときの言語」が C++ なら）、ボタンが「入力のコードを作る」になり、変数の宣言と `cin >>` の行を作ります。

```cpp
long long N;
cin >> N;
vector<long long> A(N);
for (auto& a : A) cin >> a;
vector<long long> X(N), Y(N);
for (int i = 0; i < N; i++) cin >> X[i] >> Y[i];
```

- 整数はすべて `long long`、実数は `double`、1 文字は `char`、文字列は `string` です。変数名は問題文のまま（`N`・`A`）で、縦に並ぶ組は列ごとの `vector` にします。C++ の予約語と重なる名前には末尾に `_` を付けます。
- 「solve() の入力を置き換える」は、開いている C++ ファイルの `solve()`（なければ `main()`）に、`// 入力（AtCoder Studio）` と `// 入力ここまで` のコメントで囲んでコードを書き込みます。この目印があればその間を置き換え、なければ関数の先頭（`main()` の場合は `ios::sync_with_stdio(false);`・`cin.tie(nullptr);` の後ろ）に入れます。⌘Z で元に戻せます。
- テストケースが複数ある問題では `solve()` が必要です。`main()` に `T` を読むコードを入れ、「main() に for も書く」がオンなら、`main()` の `solve();` を `for (int i = 0; i < T; i++) solve();` に書き換えます。
- 「問題を作るときに input! を入れておく」がオンなら、`main.cpp` にも同じように入れます。

#### Python の場合

選んでいる問題のフォルダが Python なら（フォルダがなければ、設定の「問題を作るときの言語」が Python なら）、ボタンが「入力のコードを作る」になり、1 行ずつ `input()` で読むコードを作ります。

```python
N, M = map(int, input().split())
A = list(map(int, input().split()))
X = [0] * M
Y = [0] * M
for i in range(M):
    X[i], Y[i] = map(int, input().split())
S = [input() for _ in range(N)]
```

- 整数は `int`、実数は `float`、文字列と 1 文字は `str` のままです。区切りのないグリッドは行ごとの文字列のリスト（`C[i][j]` で 1 文字）、空白区切りのグリッドはリストのリストになります。変数名は問題文のままで、縦に並ぶ組は列ごとのリストにします。Python の予約語や、生成コードで使う名前（`input`・`int`・`map`・`list`・`range` など）と重なる名前には、末尾に `_` を付けます。
- 入力例との照合では、行の分かれ方（1 行あたりの値の数、横に並ぶ値の長さ、縦に並ぶ行数）も確認します。合わないときは「入力例 1 と合いません（2 行目：…）」のように表示されます。
- 「solve() の入力を置き換える」は、開いている `.py` の `def solve():`（なければ `def main():`）に、`# 入力（AtCoder Studio）` と `# 入力ここまで` のコメントで囲んでコードを書き込みます。目印があればその間を置き換え、なければ関数の先頭に入れます（中身が `pass` だけなら、`pass` と置き換えます）。⌘Z で元に戻せます。
- テストケースが複数ある問題では `def solve():` が必要です。`main()` に `T = int(input())` を入れ、「main() に for も書く」がオンなら、`main()` の直下にある `solve()` を `for _ in range(T):` の中に入れます。
- 「問題を作るときに input! を入れておく」がオンなら、`main.py` にも同じように入れます。

## 実行とテスト

### 実行の対象

- 開いている `.rs` ファイルから、どのパッケージのどのバイナリを実行するかを決めます。決められないファイルを開いているときは、直前の対象をそのまま使います。
- `Cargo.toml` のないフォルダの `main.cpp`、またはそのフォルダの `test/` 内のファイルを開くと、そのフォルダが C++ の対象になります（[C++](#c)）。同じフォルダに `Cargo.toml` もあれば Rust として扱います。
- `Cargo.toml` も `main.cpp` もないフォルダの `main.py`、またはそのフォルダの `test/` 内のファイルを開くと、そのフォルダが Python の対象になります（[Python](#python)）。
- 対象のフォルダ名が問題 ID の形（例：`abc480_a`）になっていれば、問題も自動で決まります。

### テストケースのフォルダ

| 場所 | 使われるとき |
|---|---|
| `test/<バイナリ名>/` | あれば常に |
| `test/` | パッケージのバイナリが 1 つのとき（「コンテストを作る」で作ったものはこちら） |

フォルダに置くファイル：

| ファイル | 用途 |
|---|---|
| `sample-N.in`・`sample-N.out` | サンプルテストの入力と期待出力（N は 1 から） |
| `input.txt` | 「実行」で使う標準入力。なければ空の標準入力で実行します |
| `compare.json` | 比較方法と制限（[下記](#comparejson)） |
| `random-N.in`・`random-N.out` | ランダムテストで失敗したケース（IDE が保存します） |
| `interactive-N.in` | 対話テストでジャッジに渡すケース |

### 実行・サンプルテスト

- **「実行」（⌘R）**：`cargo build --release` でビルドし、`input.txt` を標準入力にして実行します。出力は「実行ログ」に表示されます。
- **「サンプルテスト」（⇧⌘R）**：`sample-N`（と `random-N`）をすべて実行し、「テスト結果」に判定・実行時間・メモリを表示します。入力・期待する出力・実際の出力を並べて見比べられます。
  - 「このケースだけ実行」「失敗したケースだけ再実行」「このケースをデバッグ」「出力を期待出力として保存」のボタンもあります。
- 実行中は、ボタンが「停止」（⌘.）に変わります。
- ビルドに失敗すると「エラー一覧」に表示されます。行を押すと、エラーの場所に移動します。
- 判定は手元でのものなので、ジャッジと同じ結果になるとは限りません。実行ログには、手元とジャッジの Rust のバージョンが表示されます。

### C++

`main.cpp` のあるフォルダ（例：`abc480/abc480_a/main.cpp`）を、C++ の 1 問として扱います。テストケースのフォルダ（`test/`）は Rust と同じです。

- **必要なもの**：Homebrew の GCC（`brew install gcc` で入る `g++-15`）。Apple の clang（Xcode Command Line Tools の `clang++`）は `#include <bits/stdc++.h>` が使えないため使いません。
  - g++ は、`settings.json` の `cpp.compiler`（g++ の絶対パス）→ `/opt/homebrew/bin/g++-15` → `PATH` 上の `g++-15` → `/usr/local/bin/g++-15` の順に探します。
- **「実行」「サンプルテスト」**：`g++-15 -std=gnu++23 -O2 -Wall -Wextra -DATCODER -DONLINE_JUDGE …` でビルドし、フォルダ内の `target/main` を実行します。オプションはジャッジの「C++23 (GCC 15.2.0)」に合わせていますが、`-march=native`・`-fopenmp` などのオプションや、Boost などのライブラリは付けません（実行ログにも表示されます）。
- コンパイルエラーや警告は「エラー一覧」に表示され、押すとその行に移動します。
- `.cpp`・`.cc`・`.cxx`・`.hpp`・`.hh`・`.h` のファイルは C++ として色分けされます。
- **AC Library**：アプリのフォルダの `libraries/ac-library/atcoder/` にあれば、ビルド時に読み込みます（`#include <atcoder/all>` など）。ジャッジと同じ 1.6 を [GitHub の atcoder/ac-library](https://github.com/atcoder/ac-library)（ライセンスは CC0）からダウンロードし、`atcoder/` フォルダをそこに置いてください。実行ログの最初に、読み込む場所（なければ「なし」）が表示されます。
- 問題やコンテストを作るときに C++ を選べます（[コンテストを作る](#コンテストを作る)）。
- 提出できます。言語は「C++23 (GCC 15.2.0)」です（[提出](#提出)）。
- 補完などの言語機能は clangd が担当します（[エディタと言語サーバー](#エディタと言語サーバー)）。
- デバッグもできます（[デバッグ](#デバッグ)）。
- ランダムテストと対話テストも使えます。生成器・愚直解・ジャッジは `examples/gen.cpp`・`examples/naive.cpp`・`examples/judge.cpp`（`main_gen.cpp` などの名前でも可）です（[ランダムテスト](#ランダムテスト)・[対話テスト](#対話テスト)）。
- 問題文から入力のコード（宣言と `cin >>`）を作れます（[input! を作る](#input-を作る)）。

### Python

`main.py` のあるフォルダ（例：`abc480/abc480_a/main.py`）を、Python の 1 問として扱います。テストケースのフォルダ（`test/`）は Rust と同じです。同じフォルダに `Cargo.toml` や `main.cpp` もある場合は、そちらの言語として扱います。

- **処理系**：ジャッジの「Python (CPython 3.13.7)」か「Python (PyPy 3.11-v7.3.20)」に合わせます。設定画面（⌘,）の「Python」の「処理系」か、`settings.json` の `python.interpreter`（`cpython`〔既定〕または `pypy`）で選びます。
- **必要なもの**：CPython なら `python3.13`（`brew install python@3.13`）、PyPy なら `pypy3.11` か `pypy3`（`brew install pypy3.11`）。IDE がインストールすることはありません。
  - 処理系は、`settings.json` の `python.cpython`・`python.pypy`（処理系の絶対パス）→ `/opt/homebrew/bin` → `PATH` → `/usr/local/bin` の順に探します。
  - ジャッジと同じバージョン（CPython は 3.13、PyPy は Python 3.11 対応のもの）でなければ、インストール方法を表示して実行しません。3.13.7 と 3.13.15 のような細かいバージョンの違いは、実行ログに表示したうえで実行します。
- **「実行」「サンプルテスト」**：`python3.13 -E -B -X int_max_str_digits=0 main.py` のように実行します。`-X int_max_str_digits=0` はジャッジと同じ指定です。`-E` で `PYTHONPATH` などの環境変数を無視し、`-B` で `__pycache__` を作らないようにしています。ビルドはありません。
- 実行の前に構文をチェックします。構文エラーがあると CE になり、「エラー一覧」からその行に移動できます。
- `.py` ファイルは Python として色分けされます。
- ランダムテストと対話テストも使えます。生成器・愚直解・ジャッジは `examples/gen.py`・`examples/naive.py`・`examples/judge.py`（`main_gen.py` などの名前でも可）です。
- 「コンテストを作る」「この問題を作る」で Python のフォルダを作るには、設定画面の「問題文」で「問題を作るときの言語」を Python にします（[コンテストを作る](#コンテストを作る)）。
- 提出できます。言語は、設定の処理系に応じて「Python (CPython 3.13.7)」か「Python (PyPy 3.11-v7.3.20)」になります（[提出](#提出)）。
- 補完などの言語機能は basedpyright が担当します（[エディタと言語サーバー](#エディタと言語サーバー)）。
- デバッグには debugpy を使います（[デバッグ](#デバッグ)）。
- 問題文から入力のコードを作れます（[input! を作る](#input-を作る)）。
- スニペットも使えます（[スニペット](#スニペット)）。

### compare.json

テストケースのフォルダに置く、比較方法と制限の設定です。書かなかった項目は既定値になります。

「コンテストを作る」「この問題を作る」で作ったフォルダには、問題に合わせた内容が最初から入っています。時間制限は問題の制限＋500 ms、メモリは問題の値です。問題文に「どれを出力しても正解」のように答えが複数ありうる書き方があれば `none`（目視で確認）、そうでなく「出力」に「誤差が 10^{-k} 以下」とあれば `float` と `1e-k` になります。読み取りが間違っていたら、手で直してください。

- 答えが複数ありうる問題で `whitespace` のままだと、正しい別解も AC にならず、提出前のサンプルテストで止まってしまいます。その場合は `"mode": "none"` にしてください（目視確認のケースがあると、提出前のテストでは止めずに確認ダイアログを出します）。設定画面の「提出」で、提出前のサンプルテスト自体をオフにすることもできます。

```json
{ "mode": "float", "abs": 1e-6, "rel": 1e-6, "timeLimitMs": 2500, "memoryLimitMiB": 1024, "randomCount": 100 }
```

| 項目 | 意味 | 既定値 |
|---|---|---|
| `mode` | `whitespace`（空白・改行の違いを無視）、`exact`（完全一致）、`float`（`abs`・`rel` の誤差の範囲なら正解）、`none`（比較しない） | `whitespace` |
| `abs`・`rel` | `float` のときの絶対誤差・相対誤差（少なくとも一方を指定） | なし |
| `timeLimitMs` | サンプルテスト・ランダムテスト・対話テストの時間制限（60000 まで。対話テストではやり取り全体にかかる） | 2500 |
| `memoryLimitMiB` | メモリ制限（65536 まで）。実行中も監視していて、超えた時点で止めて MLE にします | 1024 |
| `randomCount` | ランダムテストの回数（1〜10000） | 100 |

### ランダムテスト

- 同じパッケージの `examples/` に、生成器 `examples/<バイナリ名>_gen.rs` と愚直解 `examples/<バイナリ名>_naive.rs` を置きます（バイナリが 1 つなら `examples/gen.rs`・`examples/naive.rs` でも可）。
- C++ では `examples/gen.cpp`・`examples/naive.cpp`（`examples/main_gen.cpp`・`examples/main_naive.cpp` でも可）を、提出用と同じオプションでビルドします（ビルド結果はフォルダ内の `target/examples/` に置きます）。
- 生成器には、毎回違う seed（整数）が第 1 引数として渡されます。その seed をもとに入力を作り、標準出力に出力してください。
- 「ランダムテスト」を押すと、最大 `randomCount` 回、解答と愚直解の出力を比べます。最初に一致しなかった回で止まり、そのケースを `random-N.in`・`random-N.out` として保存します（次回からはサンプルテストでも実行されます）。

### 対話テスト

- ジャッジ（問題側の相手役のプログラム）を `examples/<バイナリ名>_judge.rs`（バイナリが 1 つなら `examples/judge.rs`）に置きます。C++ では `examples/judge.cpp`（`examples/main_judge.cpp` でも可）です。
- 「対話テスト」を押すと、解答とジャッジの標準入出力をつないで実行します。テストのフォルダに `interactive-N.in` があれば、そのパスがジャッジの第 1 引数として渡されます（なければ引数なしで 1 回だけ実行）。
- 判定は、両方が終了コード 0 で終われば AC、ジャッジが 0 以外で終われば WA、解答が異常終了すれば RE、全体で `timeLimitMs` を超えれば TLE、解答のメモリが `memoryLimitMiB` を超えれば MLE です。やり取りの内容は「テスト結果」に時系列で表示されます。
- 解答は、出力するたびに flush してください（しないと、ジャッジが待ち続けてしまうことがあります）。

## デバッグ

- エディタの行番号の左側をクリックするか F9 でブレークポイントを置き、「デバッグ」（F5）を押します。`input.txt`（「テスト結果」の「このケースをデバッグ」から始めた場合はそのケースの入力）が標準入力になります。
- デバッグを始めるとサイドバーが「実行とデバッグ」に切り替わり、止まったときにはその行が強調されて、変数・ウォッチ式・コールスタック・ブレークポイントが表示されます。
- 操作：続行・一時停止（F5）、ステップオーバー（F10）、ステップイン（F11）、ステップアウト（⇧F11）、停止（⌘.）。panic が起きたときにも止まります。
- 下の「デバッグコンソール」では、式や LLDB のコマンドを入力できます（あなたの権限で実行されます）。
- デバッグ中のプログラムは、IDE に許可した「書類」フォルダなどへのアクセス権を引き継いで動きます（問題ごとに macOS の確認が出ないようにするためです）。
- デバッグは最適化なし（dev）でビルドして実行します。ジャッジ（release）とは、実行速度やオーバーフロー時の挙動が異なります。

### C++ のデバッグ

- `g++ -g -O0 -D_GLIBCXX_ASSERTIONS` でビルドし（フォルダ内の `target/main-debug`）、`vector` や `string` も含めて変数の中身を確認できます。ブレークポイントは `.cpp`・`.hpp`・`.h` などに置けます。
- panic の代わりに、例外が投げられたとき（`throw`）と `abort` で止まります。`-D_GLIBCXX_ASSERTIONS` により、`vector` の範囲外アクセスなども `abort` として検出されます（実行・サンプルテスト・提出用のビルドには付けません）。
- 止まったときは、作業領域内のソースのうち、いちばん上のフレームが選ばれます。
- デバッグコンソールに LLDB の「`DW_TAG_member '_M_local_buf' refers to type …`」という警告が出ることがあります。GCC のデバッグ情報を LLDB が読むときのもので、変数の表示には影響しません。

### Python のデバッグ

- debugpy を使い、設定の処理系（CPython・PyPy のどちらでも）で実行します。ブレークポイントは `.py` に置けます。
- **必要なもの**：debugpy。IDE がインストールすることはありません。初めてデバッグするときにインストールのコマンドが実行ログに表示されるので、ターミナルで実行してください（処理系ごとに、アプリのフォルダの `python/cpython`・`python/pypy` にインストールします）。例：

  ```sh
  "/opt/homebrew/bin/python3.13" -m pip install --target "$HOME/Library/Application Support/io.github.ishigaki892.acdstudio/python/cpython" debugpy
  ```

- 捕まえていない例外（`KeyError`・`IndexError` など）が起きると、その行で止まります。`exit()`・`sys.exit()` では止まりません。
- debugpy の上で動かすため、通常の実行よりかなり遅くなります。
- デバッグコンソールでは Python の式を入力できます（LLDB のコマンドは使えません）。

## エディタと言語サーバー

- `.rs` ファイルを開くと rust-analyzer が起動し、補完・診断・ホバー・インレイヒントが使えます。「コンテストを作る」で作ったコンテストのフォルダでは、その中の問題をまとめて扱うので、同じコンテストの問題を行き来しても再起動しません（問題を追加したときは再起動します）。
- **C++**：C++ のフォルダ（`main.cpp` のあるフォルダ）の `.cpp`・`.hpp`・`.h` などを開くと clangd が起動し、同じ機能が使えます。
  - 必要なもの：Xcode Command Line Tools の clangd（`xcode-select --install` でインストール）と、ビルドに使う g++（[C++](#c)）。
  - IDE が clangd に、ビルドと同じオプション（`-std=gnu++23`・`-DATCODER`・AC Library の場所など）を渡します。標準ヘッダーは使用する g++ のものを読むので、`#include <bits/stdc++.h>` もエラーになりません。
  - `<コンテスト>/<問題>/` の形のフォルダでは、同じコンテストの C++ の問題をまとめて扱います。
  - clangd はフォルダ内にインデックス（`.cache/`）を作らず、`.clangd` の設定ファイルも読みません。
  - 整形スタイルは `.clang-format` で決まります。C++ でコンテストや問題を作ると、コンテストのフォルダに置かれます（LLVM スタイル、インデント 4）。`.clang-format` がないフォルダでは clangd の既定（インデント 2）になります。
  - 言語サーバーは一度に 1 つだけ動くので、Rust と C++ のファイルを行き来すると再起動します。
- **Python**：Python のフォルダ（`main.py` のあるフォルダ）の `.py` を開くと basedpyright が起動し、補完・診断・ホバー・インレイヒント・定義ジャンプ・参照検索が使えます。
  - 必要なもの：basedpyright（`brew install basedpyright`）。IDE がインストールすることはありません。
  - 設定の処理系（[Python](#python)）のバージョンで解析します。型チェックの強さは basedpyright の `standard`（pyright の既定）で、開いているファイルだけを解析します。
  - `<コンテスト>/<問題>/` の形のフォルダでは、同じコンテストの Python の問題をまとめて扱います。
  - basedpyright には整形機能がないため、整形（⇧⌥F や ⌘S 時の整形）はしません。⌘S は保存だけです。
  - Rust・C++ と同じく、言語を切り替えると言語サーバーが再起動します。
- 定義へジャンプ（F12）、参照検索（⇧F12。Esc で閉じる）、整形（⇧⌥F。⌘S でも整形してから保存）が使えます。
- 次のようなファイルへジャンプした場合は、読み取り専用のタブで開きます：標準ライブラリや依存クレート、C++ の標準ヘッダー（使用する g++ と SDK のもの）と AC Library、Python の型情報（basedpyright 付属の typeshed の `.pyi`）・標準ライブラリ・site-packages（設定の処理系のもの）。
- 同じ名前のファイルを複数開くと、タブに区別できるフォルダ名（例：`…/abc339_a`）が付きます。フルパスは、タブにマウスを乗せると表示されます。タブが並びきらないときは、タブの列の上でホイールを回すと横にスクロールできます。
- タブの列の下のパンくずリストには、作業領域からのフォルダの道筋とファイル名、カーソル位置の記号とそれを囲む記号が表示されます（例：`abc480 › a › src › main.rs › impl Foo › bar`）。
  - 記号の情報は言語サーバー（rust-analyzer・clangd・basedpyright）から取得し、編集が止まってから 0.5 秒ほどで更新されます。言語サーバーが動いていないとき（信頼していないフォルダなど）は表示されません。
  - Markdown（`.md`）では見出しを表示します（`#` で始まる行だけ。コードブロック内は除きます）。
  - 各段を押すと一覧が表示されます。フォルダの段はそのフォルダの中身、ファイルの段は同じフォルダの中身（フォルダを選ぶとその中身に切り替わり、ファイルを選ぶと開きます）、記号や見出しの段は同じ階層の記号・見出しの一覧（選ぶとその場所に移動）です。↑↓ で選び、Enter で決定、Esc で閉じます。
  - 読み取り専用のタブではファイル名だけを表示します。パンくずリストは設定の「表示」で非表示にできます。
- 行頭のインデントは、1 段（4 スペースまたはタブ 1 つ）ごとに薄い色で塗り分けられます。
- エラーや警告のある行は背景に色が付き、行末にメッセージが表示されます（いちばん重要度の高いもの。ほかにもあれば「（ほか N 件）」）。
- 言語サーバーの調子が悪いときは、メニューの「ファイル」→「言語サーバーを再起動」を試してください。
- ファイルは自動で保存されます（⌘S ですぐに保存）。ほかのアプリでファイルが変更されたときは、「再読み込み」するか「上書き」するかを聞かれます。
- 保存できないファイル（ほかのアプリで削除された、書き込み権限がないなど）があると、タブを閉じる・アプリを終了する・別のフォルダを開くときに、変更を破棄するかを確認されます。

## スニペット

アプリのフォルダ（[データの場所](#データの場所)）にある言語ごとのファイルに、VS Code と同じ形式でスニペットを書くと、その言語のファイルで使えます（ほかの言語のファイルには出ません）。コメント（`//`・`/* */`）や末尾のカンマも書けます。

| 言語 | ファイル | 使えるファイル |
|---|---|---|
| Rust | `snippets-rust.json` | `.rs` |
| C++ | `snippets-cpp.json` | `.cpp`・`.hpp`・`.h` など |
| Python | `snippets-python.json` | `.py` |

以前のバージョンの `snippets.json` は、`snippets-rust.json` がなければ、IDE が読み込むときに `snippets-rust.json` へ名前を変えます。

```json
{
  "入力を読む": {
    "prefix": ["rd", "読む"],
    "body": ["let ${1:n}: usize = sc.next();", "$0"],
    "description": "1 つ読む"
  }
}
```

- `prefix` の文字を入力すると、補完の候補に ✂ のアイコン付きで表示されます。Tab か Enter で展開し、Tab・⇧Tab で入力欄（`$1`・`${1:既定の文字}`）を移動します。最後は `$0` の位置に移ります。2 行目以降は、挿入した行のインデントに合わせます（行頭のタブは 4 スペースになります）。
- 言語サーバーが動いていなくても、信頼していないフォルダでも使えます。
- ファイルを書き換えたら、IDE のウィンドウに戻ったときに読み込み直します。読み込めない項目があればその名前をお知らせし（ほかの項目は使えます）、JSON として読めないときは、以前のスニペットを使い続けてお知らせします。
- 設定画面（⌘,）の「スニペット」に、言語ごとに今読み込めているスニペットの一覧が表示されます。「ファイルを開く」で、その言語のファイルを既定のテキストエディタで開きます（なければ空のファイルを作ります）。
- 「VS Code から取り込む」で、VS Code のスニペット（`~/Library/Application Support/Code/User/snippets/` の `rust.json`・`cpp.json`・`python.json`）を、対応する言語のファイルにコピーします。確認ダイアログが出たあと、今のファイルは同じフォルダに `snippets-rust.backup-<時刻>.json`（C++ は `snippets-cpp.backup-…`、Python は `snippets-python.backup-…`）として退避されます（言語ごとに新しいものから 5 つまで残します）。VS Code のファイルを自動で読み込むことはありません。
- 選択肢（`${1|a,b|}`）は最初の候補が既定の文字になります。変数（`$TM_SELECTED_TEXT` など）は空になります。本文中に文字として `${` や `#{` を書くと入力欄として扱われてしまうため、書けません。

## 提出

- 右下の「提出結果」の「ログイン」を押すと、AtCoder のログイン用のウィンドウが開くので、そこでログインしてください。パスワードが IDE に渡ることはありません。ログインのセッションは macOS のキーチェーンに保存します。
- 開催中のコンテストの問題で「提出」を押すと、まずサンプルテストが実行されます（結果は「テスト結果」に表示）。すべて AC のときだけ次に進み、AC でないケースがあるときや途中で止めたときは提出しません。サンプルがない問題（インタラクティブ問題など）では、テストをせずに次に進みます。
- 続いて提出前のチェックを行い、確認ダイアログが表示されます。「提出する」を選んだときだけ提出します。チェックする内容は次のとおりです。
  - **Rust**：別ファイルの `mod`、ジャッジにないクレート、バージョンの違い、バイナリ名と問題の記号の食い違い。
  - **C++（`main.cpp`）**：自作のヘッダーを読む `#include "…"`、手元の GCC のバージョンがジャッジ（15.2.0）と違うこと。
  - **Python（`main.py`）**：同じフォルダの自作モジュール（`lib.py`・`lib/` など）や相対 `import`、ジャッジの言語一覧にないパッケージの `import`（PyPy は CPython よりパッケージが少なく、`numba` などがありません）、手元の処理系のバージョンがジャッジ（CPython 3.13.7・PyPy 7.3.20）と違うこと。`import` は手元の処理系で解析します（文字列やコメントの中は数えません）。処理系が見つからないときは、チェックできなかったことを注意として表示します。
    - ジャッジのパッケージは、言語一覧のパッケージ名を `import` の名前に読み替えて比べます（`scikit-learn` は `sklearn`、`ac-library-python` は `atcoder`、`z3-solver` は `z3` など）。一覧にはないものの、ほかのパッケージの依存として入っているもの（PyPy の `dateutil` など）にも注意が出ることがあります。
- 提出する言語は、提出ページの選択肢から選びます。Rust は「Rust」で始まる最初のもの、C++ は「C++23 (GCC 15.2.0)」、Python は設定の処理系に応じて「Python (CPython 3.13.7)」か「Python (PyPy 3.11-v7.3.20)」です。見つからないときは提出しません（Codon は選びません）。
- 設定画面の「提出」で、次の 2 つを変更できます（[設定](#設定)）。
  - **提出前のサンプルテスト**（初期状態はオン）：オフにすると、テストをせずに次に進みます。
  - **確認ダイアログ**（初期状態は表示）：表示しない設定にしても、ダイアログを省くのは、今のソースでサンプルテストがすべて AC になっていて、提出前のチェックで注意がないときだけです（サンプルがない、目視確認のケースがある、テストのあとにファイルを変えた、注意がある、のいずれかなら表示します）。省いたときは、実行ログに「確認のダイアログを省いて提出しました」と表示されます。表示しない設定で保存するときは、OS の確認が出ます。
  - サンプルテストに通ったかどうかは、IDE が実行履歴で確認します。
- 提出後は「提出結果」に判定が表示され、確定するまで追いかけます。「更新」で読み込み直し、「詳細」で公式の詳細ページを開けます。
- 開催期間外の問題は提出しません。代わりに「コードをコピーして公式の提出ページを開く」で、ブラウザから提出できます。
- 「提出」のショートカットキーは、初期状態では割り当てていません（[キーの割り当て](#キーの割り当て)）。

### コンテストの提出状況

- アクティビティバーの「コンテスト」（旗のアイコン）で、問題文の欄に表示している問題のコンテストについて、問題ごとの提出状況を表示します。開いているファイルを切り替えて問題が変われば、コンテストも切り替わります。
  - ✓（緑）：AC した提出がある。✗：提出はあるが AC していない（最後の判定と提出回数を表示）。・：まだ提出していない。
- AtCoder の「自分の提出」ページ（そのコンテストの分だけ）を、ログインのセッションで読み込みます。読み込むのは、「コンテスト」を開いたとき（前回から 1 分以上たっていれば）・コンテストが切り替わったとき・「更新」を押したとき・ログインしたときだけです。ページは 1 秒ずつ間隔をあけて、新しい順に 10 ページまで読みます（それを超える場合はお知らせします）。
- IDE から提出したものは、通信せずに一覧に反映します（判定を追っている間の状態も表示します）。
- 行を押すと、問題文の欄でその問題を選びます。フォルダから決まった問題と結び付いている場合は、結び付きを外してその問題を表示します（問題の選択欄の「フォルダの問題に戻す」で戻せます）。
- ログインしていないときは「ログイン」ボタンが表示されます。読み込めなかったときは理由が表示され、前回の結果はそのまま残ります。
- 「自分の提出を開く」で、公式ページを既定のブラウザで開きます。

| 定義へジャンプ | F12 | `goToDefinition` |

| 検索 | ⇧⌘F | `showSearch` |
| 実行とデバッグ | ⇧⌘D | `showDebug` |

- 割り当ては、設定画面か、アプリのフォルダの `settings.json` の `keyBindings` で変更できます（[設定](#設定)）。一覧に書いたコマンドはその割り当てを、書いていないコマンドは既定の割り当てを使います。変更は、IDE のウィンドウに戻ったときに反映されます（再起動は不要です）。
- 1 つの割り当ての書き方（`meta` は ⌘、`alt` は ⌥）：

  ```json
  { "command": "submit", "key": "enter", "meta": true, "ctrl": false, "alt": false, "shift": true }
  ```

- `key` にはキーの名前を書きます（英字は小文字。例：`r`、`.`、`f12`、`enter`）。⌥ を使う割り当ては、英字・数字ならキーの位置でも判定します。
- キーの割り当てを外すときは `"key": ""` と書きます（既定の割り当ても使わなくなります）。
- 読めない割り当てや、存在しないコマンドは無視され、ファイル一覧の下にお知らせが表示されます。同じキーを 2 つのコマンドに割り当てたときもお知らせが出ます（一覧で先に書いたほうが使われます）。
- ファンクションキーは、macOS の設定によっては、そのまま押すと画面の明るさ調整などになることがあります。その場合は fn キーを押しながら押してください。

## 設定

⌘,、メニューの「AtCoder Studio」→「設定…」、またはアクティビティバーの下の歯車で、設定画面が開きます。

- **「キー」**：コマンドごとに「変更」（押したキーを割り当てる。Esc で取り消し）・「なし」・「既定に戻す」が使えます。ほかのコマンドと同じキー、⌘・⌃・⌥ を含まないキー（F1〜F20 は使えます）、macOS やメニューで使うキー（⌘C・⌘Z など）は割り当てられません。
- **「色」**：色の選択と濃さ（0〜100%）、「既定に戻す」。
- **「表示」**：インデントの色分け・診断のある行の表示・パンくずリストのオン／オフと、エディタと問題文の文字の大きさ。
- **「問題文」**：問題文の欄の見出しに並べるボタン（並べないものは「…」の一覧に入ります）、問題を作るときの言語、問題を作るときに `input!`（C++・Python では入力のコード）を入れておくか、テストケースが複数のとき `main()` に `for` も書くか（[input! を作る](#input-を作る)）。
- **「提出」**：提出前のサンプルテストと確認ダイアログ（[提出](#提出)）。
- **「Python」**：`main.py` を実行する処理系（CPython 3.13・PyPy 3.11。[Python](#python)）。処理系のパスは `settings.json` に書きます。
- **「スニペット」**：今読み込めているスニペットの一覧と、「ファイルを開く」「VS Code から取り込む」（[スニペット](#スニペット)。保存とは関係ありません）。
- **「テンプレート」**：雛形のファイル（`templates/main.rs`・`templates/dependencies.toml`・`templates/main.cpp`・`templates/main.py`）があるかどうかと、「テンプレートのフォルダを開く」（Finder で開きます。フォルダがなければ作ります。[雛形](#雛形)。保存とは関係ありません）。

色と表示は、変更するとすぐ画面に反映されます。「保存」で `settings.json` に書き込み、「キャンセル」（または Esc）で元に戻ります。

- 保存で書き換えるのは、キー・色・表示・問題文・提出の項目と、Python の処理系の選択だけです。`settings.json` に自分で書いたほかの項目はそのまま残ります。キーは、すべてのコマンドの割り当てを書き出します（同じコマンドに 2 つ以上書いていた場合は、先のものだけになります）。
- 設定画面を開いている間に `settings.json` が外部で変更された場合は、画面の内容が読み込み直されます（保存はしません）。

設定画面の「JSON で開く」で、`settings.json` を既定のテキストエディタで開けます。書き換えて保存し、IDE のウィンドウに戻ると反映されます。JSON の書き方が崩れているときは今の設定のまま動き、ファイル一覧の下にお知らせが表示されます（直して戻れば反映されます。崩れている間は、設定画面から保存できません）。

書き方の例（書かなかった項目は既定値になります）：

```json
{
  "version": 1,
  "keyBindings": [ … ],
  "colors": { "indent-rainbow-1": "rgba(255, 255, 64, 0.25)", "syntax-keyword": "#ff8080" },
  "editor": { "indentRainbow": true, "errorLens": true, "breadcrumbs": true, "fontSize": 13 },
  "problem": { "fontSize": 13, "buttons": ["makeInput", "saveSamples"], "mainLoop": false, "fillInput": false },
  "submit": { "testBeforeSubmit": true, "confirmDialog": true }
}
```

- `colors`：色の名前と CSS の色（`#rrggbb`、`rgba(…)` など）。名前は `src/styles/tokens.css` の色の変数名から先頭の `--` を除いたものです（例：`bg-base`、`syntax-keyword`、`indent-rainbow-1`、`lens-error-line`）。書いた色だけが変わります。
- `editor.indentRainbow`・`editor.errorLens`・`editor.breadcrumbs`：インデントの色分け、診断のある行の色とメッセージ、パンくずリストのオン／オフ。
- `editor.fontSize`・`problem.fontSize`：エディタと問題文の欄の文字の大きさ（8〜32 の整数、px）。
- `problem.buttons`：問題文の欄の見出しに並べるボタン。`makeInput`（input! を作る）・`saveSamples`（サンプルを保存）・`refresh`（再取得）・`openPage`（公式ページ）・`createProblem`（この問題を作る）から選びます。表示される順番は書いた順ではなく、この順です。
- `problem.fillInput`：「コンテストを作る」「この問題を作る」のときに、`input!`（C++・Python では入力のコード）を入れておくか（[input! を作る](#input-を作る)）。
- `problem.language`：問題やコンテストを作るときの言語（`rust`・`cpp`・`python`）。
- `problem.mainLoop`：テストケースが複数のとき、入力の置き換えで `main()` に `for`（Rust なら `input!` と `for _ in 0..t { solve(); }`）まで書くか（[input! を作る](#input-を作る)）。
- `submit.testBeforeSubmit`・`submit.confirmDialog`：提出前のサンプルテストと確認ダイアログ（[提出](#提出)）。手で `confirmDialog` を `false` にした場合、OS の確認は出ません。
- `cpp.compiler`：C++ で使う g++ の絶対パス。空なら自動で探します（[C++](#c)）。
- `python.interpreter`：Python の処理系（`cpython`・`pypy`）。`python.cpython`・`python.pypy`：処理系の絶対パス。空なら自動で探します（[Python](#python)）。
- 読み取れない項目は既定値を使い、お知らせが表示されます。

## 既知の制限

- **⌃Space**：エディタで補完を手動で出すキーですが、macOS の「入力ソースの切り替え」と重なっていると、入力ソースが切り替わってしまいます。補完は入力中に自動で出るので普段は困りませんが、手動で出したい場合は、macOS の設定（キーボード → キーボードショートカット → 入力ソース）で切り替えのキーを変更してください。
- **F11**：macOS の機能（デスクトップを表示など）と重なることがあります。ステップインに使う場合は、macOS の設定で外すか、`settings.json` で `stepIn` のキーを変更してください。
- **Rust が見つからない**：「cargo が見つかりません」と表示されたら、[rustup](https://rustup.rs) で Rust をインストールしてください。
- **GCC が見つからない**：C++ で「g++-15 が見つかりません」と表示されたら、ターミナルで `brew install gcc` を実行してください。
- **clangd が見つからない**：C++ のファイルで「clangd が要ります」と表示されたら、ターミナルで `xcode-select --install` を実行してください。
- **basedpyright が見つからない**：`.py` のファイルで「basedpyright が要ります」と表示されたら、ターミナルで `brew install basedpyright` を実行してください。
- **ジャッジとの違い**：手元での判定・実行時間・メモリは目安です。ジャッジのバージョン（rustc 1.89.0、edition 2024 など）は、AtCoder の言語アップデートで変わることがあります。
- **提出**：参加登録が必要なコンテストに未登録のまま提出したときの動作は確認していません。Rust の選択肢が複数ある場合の動作も、まだ確認していません（「Rust」で始まる最初のものを選びます）。C++ の Clang 版や IOI-Style、Python の Codon では提出しません（対応していません）。
- **出力の末尾の改行**：サンプルテストの `whitespace`（空白の違いを無視）は、AtCoder 公式の説明の文言どおり、期待出力が改行で終わるなら、出力も空白で終わることを求めます（`print!` で改行を出さないと AC になりません）。実際のジャッジがどう判定するかは確認していません。
- **安全性**：信頼したフォルダのコードは、制限なし（サンドボックスなし）で実行されます。デバッグ中は、デバッグコンソールから LLDB のコマンドを使えます。ログインのセッションはキーチェーンに保存しますが、同じユーザーのほかのプログラムから読める場合があります。
- **Windows**：対応を確認していません。
